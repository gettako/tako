## Architectural Philosophy

Tako is designed with clear architectural boundaries: a unified Go control plane, an embedded SQLite database, and decentralized worker agents that manage local Docker engines. Rather than using distributed consensus algorithms or running multiple background databases, Tako keeps state centralized in SQLite while distributing container execution to worker nodes.

## Core Components

### 1. Tako Master Server (`tako-server`)

The master server is written in Go and acts as the central orchestrator and API gateway:

- **HTTP REST & Server-Sent Events (SSE):** Built on the Chi router (`github.com/go-chi/chi/v5`). Provides REST endpoints under `/api/v1` and real-time SSE event channels (`/api/v1/events`) for streaming deployment logs and cluster telemetry to web clients.
- **gRPC Control Server:** Listens on port `50051`. Maintains long-lived, multiplexed HTTP/2 streams with enrolled worker nodes. Dispatches deployment tasks, collects host metrics, and streams terminal logs.
- **Background Orchestrators:**
  - *Liveness Watcher:* Scans registered nodes every 5 seconds. If a node fails to report a heartbeat within 15 seconds, its state transitions to `offline`.
  - *Autoscaler Loop:* Evaluates CPU and memory consumption every 15 seconds to adjust service replica counts between defined thresholds.
  - *Retention Cleaner:* Runs daily to purge old deployment logs, temporary files, and historical metric records past the configured retention window (default: 90 days).

### 2. Embedded Database (`SQLite WAL`)

Tako avoids running an external database engine:

- **Write-Ahead Logging (WAL):** SQLite operates in WAL mode with `PRAGMA foreign_keys = ON;` and `PRAGMA busy_timeout = 5000;`. Concurrent read requests run simultaneously without locking writers.
- **Credential Encryption:** Sensitive values (such as environment secrets and Git tokens) are encrypted with AES-256-GCM before being committed to disk.
- **Zero Configuration Backup:** Creating a complete cluster backup is as straightforward as executing SQLite online backup commands or copying the single `.db` file.

### 3. Tako Console (`tako-console`)

The web dashboard is a Next.js 16 application with React 19 and Tailwind CSS v4:

- **Headless UI Primitives:** Built with `@base-ui/react` and styled according to the `base-vega` design preset.
- **Real-Time Telemetry:** Connects to the master server via Server-Sent Events (SSE) to render live deployment logs, terminal sessions, and cluster charts without polling.

### 4. Tako Worker Agent (`tako-agent`)

The worker daemon runs on every server that executes user containers:

- **Outbound gRPC Client:** Connects outbound to the master server using a pre-shared enrollment token. The connection carries deployment tasks, container action signals, and metric telemetry.
- **Docker Engine SDK Integration:** Communicates directly with the Docker daemon unix socket (`/var/run/docker.sock`) using official Go Docker client libraries.
- **Dynamic Traefik Configuration:** Manages routing by writing atomic YAML files directly into `/etc/tako/traefik/dynamic`.

### 5. Edge Proxy (`Traefik v3`)

Every node running web workloads includes a local Traefik v3 instance:

- **File Provider:** Traefik monitors `/etc/tako/traefik/dynamic` using filesystem notifications (`inotify`) to hot-reload routing rules with zero downtime.
- **Automated TLS (Let's Encrypt):** Validates HTTP-01 ACME challenges and manages TLS certificates automatically.
