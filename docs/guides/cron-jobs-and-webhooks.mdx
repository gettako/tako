## Scheduled Cron Jobs

Tako allows you to schedule commands inside your running container without setting up separate cron daemon containers:

### Adding a Cron Job:
1. Open your Service and select the **Settings** tab.
2. Scroll to the **Cron Jobs** section.
3. Click **Add Cron Job**.
4. Define your schedule and command:
   - **Name:** e.g. `Nightly Cleanup`
   - **Cron Expression:** Standard 5-field syntax (e.g. `0 2 * * *` for every night at 2:00 AM, or `*/15 * * * *` for every 15 minutes).
   - **Command:** The shell command to run inside the container (e.g. `python scripts/cleanup.py` or `php artisan schedule:run`).
5. Click **Save Cron Job**.

Tako's master orchestrator tracks the cron schedule and dispatches a `TASK_EXEC` gRPC message to the agent at the appointed time, capturing output in the Cron Execution History dialog.

## Deploy Webhooks

Deploy webhooks allow you to trigger a redeployment from external services (such as GitHub, GitLab, Docker Hub, or a CI/CD script):

1. In the Service **Settings** tab, scroll to **Deploy Webhooks**.
2. Click **Generate Webhook**.
3. Tako generates a unique, cryptographically random webhook URL:
   ```text
   POST https://<YOUR_TAKO_URL>/api/v1/services/{id}/deploy/webhook?token=sec_abc123...
   ```
4. You can trigger a new deployment anytime by issuing a POST request:
   ```bash
   curl -X POST "https://<YOUR_TAKO_URL>/api/v1/services/{id}/deploy/webhook?token=sec_abc123..."
   ```
5. View past webhook dispatches and response statuses in the **Webhook Deliveries Table**.
