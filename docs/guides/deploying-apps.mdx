## Supported Deployment Sources

Tako supports multiple source workflows for your workloads:

<CardGroup cols={2}>
  <Card title="Git Repositories" icon="git-branch">
    Deploy from any public or private Git repository (GitHub, GitLab, Bitbucket, Gitea) via HTTPS or SSH credentials.
  </Card>
  <Card title="GitHub App Integration" icon="github">
    Direct repository selection and automatic push-to-deploy webhooks without managing personal access tokens.
  </Card>
  <Card title="Pre-built Container Images" icon="box">
    Deploy images directly from Docker Hub, GitHub Packages (`ghcr.io`), Quay.io, or self-hosted private registries.
  </Card>
  <Card title="Docker Compose Stacks" icon="layer-group">
    Define multi-container workloads, services, internal networking, and shared volumes in a single Compose file.
  </Card>

## 1. Deploying from a Git Repository

1. In your Project, click **Create Service**.
2. Select **Git Repository** as the source.
3. Fill in the repository details:
   - **Repository URL:** e.g. `https://github.com/my-org/my-app.git` or `git@github.com:my-org/my-app.git`
   - **Branch:** e.g. `main` or `production`
   - **Build Context Directory:** Root directory of your code (defaults to `./`)
   - **Dockerfile Path:** Relative path to your Dockerfile (defaults to `Dockerfile`)
4. Configure your container port (e.g. `3000`).
5. Click **Deploy**.

---

## 2. Deploying a Docker Image

If your CI/CD pipeline builds images externally (e.g. via GitHub Actions):

1. Select **Docker Image** as the source.
2. Enter the full image name and tag:
   ```text
   ghcr.io/my-org/my-api:v1.2.0
   ```
3. If the registry is private, select your saved credentials from **Settings > Registries**.
4. Configure port and environment variables.
5. Click **Deploy**.

---

## 3. Deploying Multi-Container Docker Compose

For microservices or multi-container architectures:

1. Select **Docker Compose** as the build type.
2. Paste your `docker-compose.yml` definition into the web editor:

```yaml
version: "3.8"
services:
  web:
    image: node:20-alpine
    command: npm start
    ports:
      - "3000"
    environment:
      - REDIS_HOST=cache
    depends_on:
      - cache

  cache:
    image: redis:7-alpine
    volumes:
      - redis-data:/data

volumes:
  redis-data:
```

3. Tako will automatically configure internal networking so services can resolve each other by container name.

## Resource Limits & Health Checks

In the service **Settings** tab, you can define:

- **CPU Limit:** e.g., `0.5 vCPU`, `1 vCPU`, `2 vCPU`.
- **Memory Limit:** e.g., `256 MB`, `512 MB`, `1 GB`, `2 GB`.
- **Health Check Probe:** Path (e.g. `/health`), Port, Probe Interval, and Timeout. You can click **Test Health Check** to verify the probe before launching!
