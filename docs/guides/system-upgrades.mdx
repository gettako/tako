## Overview

Tako is delivered as immutable Docker container images for the master control plane (`tako-server`, `tako-console`, `traefik`) and a lightweight Go binary daemon for the worker agent (`tako-agent`).

Because all platform metadata is persisted in the embedded SQLite database (`/opt/tako/data/sqlite/tako.db`) and worker configurations are stored in `agent.json`, upgrading Tako to newer releases preserves all projects, services, SSL certificates, and active deployments without data loss.

---

## 1. Upgrading the Master Server

You can upgrade the Tako Master Server using either Docker Compose or the universal installer script:

### Method A: Using Docker Compose (Recommended)

1. SSH into your master server with root or sudo privileges:
   ```bash
   cd /opt/tako
   ```
2. Pull the latest release images:
   ```bash
   docker compose pull
   ```
3. Re-launch the containers with the newly pulled images:
   ```bash
   docker compose up -d
   ```
4. Verify all master containers are running healthy:
   ```bash
   docker compose ps
   ```

### Method B: Using the Universal Installer

Running the installer script on an existing installation automatically detects existing `.env` secrets, pulls updated images, and restarts the control plane:

```bash
curl -fsSL https://gettako.dev/install.sh | bash
```

---

## 2. Upgrading Remote Worker Nodes

Worker nodes run workloads independently of the master server. Upgrading a worker node does not restart active user containers:

1. SSH into the remote worker server:
   ```bash
   cd /opt/tako
   ```
2. Pull the updated agent container:
   ```bash
   docker compose pull agent
   ```
3. Restart the agent service:
   ```bash
   docker compose up -d agent
   ```
4. The worker agent will read `/opt/tako/data/agent/agent.json`, reconnect to the master server via gRPC within seconds, and resume streaming telemetry.

---

## Post-Upgrade Verification Checklist

- [ ] Log into the Tako Console and check that the cluster version in **Settings** matches the expected release.
- [ ] Verify that all registered nodes in the **Nodes** view display an **Online** status.
- [ ] Confirm deployed user applications are serving HTTP/S traffic without interruption.
- [ ] Verify Server-Sent Events (SSE) live logs are streaming on the deployment view.
