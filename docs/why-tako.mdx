## The Problem with Traditional Self-Hosted PaaS

Platform-as-a-Service tools have dramatically improved developer productivity. However, self-hosting traditional PaaS solutions often introduces new operational hurdles:

1. **Heavy Resource Footprint:** Many tools require spinning up PostgreSQL, Redis, RabbitMQ, and numerous backend workers just to run their web dashboard. A $5/mo or $10/mo VPS (1 GB – 2 GB RAM) often exhausts its memory before running a single application container.
2. **Insecure Worker Node Management:** Multi-server clustering typically requires opening SSH port 22 to the public internet and providing the master server with root SSH private keys, or opening unauthenticated HTTP daemon ports.
3. **Flaky Deployments & Traffic Drops:** Deployments that swap containers without health checks or graceful zero-downtime cutover cause intermittent 502 Bad Gateway errors for active users.
4. **Complex State Management:** Managing distributed state across multi-server setups frequently requires distributed consensus clusters (e.g. etcd, ZooKeeper) that are brittle and hard to maintain.

## Architectural Principles of Tako

Tako was engineered to resolve these challenges through clean, modern systems design.

### 1. Minimal Resource Footprint (Go + SQLite WAL)
The master orchestrator (`tako-server`) is written in Go and compiles to a single native binary. All platform data—services, deployments, node heartbeats, environment variables, and audit logs—is stored in an embedded SQLite database using **Write-Ahead Logging (WAL)** mode.
- Idle control plane memory: **< 50 MB RAM**.
- Zero external database containers required.
- Instant crash recovery and atomic transactions.

### 2. Outbound-Only Worker Architecture (gRPC)
In Tako, the master server **never initiates inbound network connections into worker nodes**.
Instead, worker nodes run `tako-agent`, which connects out to the master server over a persistent, multiplexed **gRPC stream (HTTP/2)**:
- **No SSH Port 22 required** on remote worker nodes.
- **No inbound firewall ports needed** on worker nodes.
- **NAT-Friendly:** Worker nodes can run in private subnets, behind carrier-grade NAT, or on dynamic home broadband IPs without port forwarding.

### 3. Dynamic Traefik v3 Edge Routing
Rather than writing fragile NGINX reload scripts that drop active TCP connections, Tako uses Traefik v3. The agent writes Traefik dynamic file configurations atomically:
- **Automatic Let's Encrypt:** Zero-configuration TLS certificates via HTTP-01 challenges.
- **Hot-Reloading without Downtime:** Traefik detects dynamic configuration changes in milliseconds without restarting or dropping in-flight HTTP connections.

### 4. Zero-Downtime Deployment Promotion Gates
Tako enforces a strict deployment verification lifecycle:
1. When a new deployment is triggered, the agent pulls or builds the new Docker image.
2. The agent launches the new container on an isolated private port and creates a temporary **preview route**.
3. The agent executes configured HTTP health checks against the new container.
4. If health checks pass, Traefik atomically cuts over public traffic to the new container and prunes the old version.
5. If health checks fail or time out, the new container is safely stopped, and the existing healthy deployment remains untouched.

## Feature Comparison Matrix

| Feature | Tako | Coolify | Dokploy | Kubernetes / K8s |
| :--- | :--- | :--- | :--- | :--- |
| **Control Plane Idle RAM** | **~45 MB** | ~800 MB – 1.5 GB | ~300 MB – 600 MB | ~1.5 GB – 3 GB+ |
| **Primary Database** | **Embedded SQLite (WAL)** | PostgreSQL + Redis | PostgreSQL | etcd cluster |
| **Worker Inbound Ports** | **0 (Outbound gRPC only)** | Port 22 (SSH root access) | Port 22 (SSH access) | Inbound API & Kubelet |
| **NAT / Private Subnet Worker** | **Full Native Support** | Complex (Requires VPN/Tunnels) | Complex (Requires VPN) | Requires overlay network |
| **Zero-Downtime Cutover** | **Dynamic Traefik v3 Gates** | Traefik | Traefik | RollingUpdate Pods |
| **In-Browser Terminal** | **Included (xterm.js + VFS)** | Terminal available | Web terminal | `kubectl exec` |
| **Passkey / WebAuthn Support** | **Built-in** | Limited | Limited | External OIDC |
| **Single-Binary Agent** | **Yes (~20 MB Go)** | Docker Engine script | Docker Engine script | Kubelet + Containerd |
